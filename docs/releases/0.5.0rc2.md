# RoyalShuffle 0.5.0rc2

RoyalShuffle 0.5.0rc2 is the current Linux CLI release candidate. Native Linux
acceptance is the remaining gate before stable Linux 0.5.0. It has been
validated under Ubuntu WSL2 and automated Ubuntu CI, but WSL does not satisfy
the native-Linux acceptance gate.

External testers should use the attached
`royalshuffle-0.5.0rc2-py3-none-any.whl`. Do not install the source archive or
clone the default branch for acceptance testing. Use Python 3.10 or 3.12 and a
fresh virtual environment:

```bash
python3 -m venv ~/royalshuffle-0.5.0rc2-test
source ~/royalshuffle-0.5.0rc2-test/bin/activate
python -m pip install --upgrade pip
python -m pip install "https://github.com/royalj54/royalshuffle/releases/download/v0.5.0-rc.2/royalshuffle-0.5.0rc2-py3-none-any.whl"
royalshuffle --version
royalshuffle diagnostics
```

The version command must report `RoyalShuffle 0.5.0rc2`. Spotify
authentication requires an account allowlisted as a user of the RoyalShuffle
Spotify Developer app.

Follow the
[native Linux acceptance checklist](https://github.com/royalj54/royalshuffle/blob/v0.5.0-rc.2/docs/native-linux-acceptance.md)
and report the completed results to the release coordinator. For a failure,
include the Linux distribution, Python and RoyalShuffle versions, exact command
and exit code, redacted `royalshuffle diagnostics` output, authentication path
used, and any partial Spotify playlist ID reported by the command.

Changes in rc2:

- CSV import now uses strict local Spotify URI validation instead of per-track
  catalog lookups.
- Large imports no longer generate hundreds of Spotify catalog requests.
- A 500-track import now requires only the expected playlist creation and
  population calls.
- Exact CSV order and duplicate tracks are preserved.
- Playlist population remains batched at up to 100 tracks per request.
- CLI import now reports coarse progress during playlist creation and
  population.
- Partial-write preservation, quota classification, and ambiguous-write safety
  remain intact.
